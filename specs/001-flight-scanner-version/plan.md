# Implementation Plan: Update the Flight-Scanner Version

**Branch**: `001-flight-scanner-version` | **Date**: 2026-10-05 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-flight-scanner-version/spec.md`

## Summary

Bring the dashboard's flight-scanner module (the **fly-over-tracker** module that supplies the
closest-aircraft tile, aircraft list, and flight map) up to its latest published release,
**0.5.0**, for both knobs it is consumed through: the embedded widget package
(`@sousa99/fly-over-tracker-components`) and the backend service image
(`ghcr.io/sousa99/fly-over-tracker-backend`). The update is declaration-only — no widget inputs,
endpoints, or runtime configuration change — so it touches the dependency declaration, the
lockfile, the backend image-tag default/override, and the version documentation. The other three
modules stay untouched.

## Technical Context

**Language/Version**: TypeScript 5.9 (strict), React 19, Vite 6, Node.js >= 24

**Primary Dependencies**: `@sousa99/fly-over-tracker-components` (widget package; currently
`^0.4.2`, target `^0.5.0`); `@sousa99/homesweethome-config` presets (lint/format/typecheck)

**Storage**: N/A — runtime block behavior lives in `public/config.json`; no schema change

**Testing**: Vitest 3 + `@testing-library/react` (jsdom); existing suites
`tests/config.test.ts`, `tests/status.test.ts`, `tests/dashboard.test.tsx`

**Target Platform**: Static SPA served by nginx; module backends + dashboard run via Docker
Compose (`ghcr.io/sousa99/*` images)

**Project Type**: Single web application (dashboard) at the repository root

**Performance Goals**: No change — TV dashboard is scroll-free and rem-based; version bump adds no
runtime work beyond the widget's existing refresh loop

**Constraints**: Must not introduce scrolling layouts or fixed px; `deploy/nginx.conf` and
`vite.config.ts` proxy contracts must stay in sync (unchanged by this feature); CI installs with a
frozen lockfile, so `pnpm-lock.yaml` must match the new declarations

**Scale/Scope**: 1 module version bump; 1 dependency specifier; 2 compose image references (backend

- MCP); 2 documentation/default files (`docs/versions.md`, `.env.example`); 1 lockfile
