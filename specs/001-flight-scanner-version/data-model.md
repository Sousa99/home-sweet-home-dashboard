# Phase 1 Data Model: Update the Flight-Scanner Version

This feature has no runtime data store. The "entities" below are the declaration and
documentation artifacts whose values must stay consistent. Field names are shown for precision;
paths are repository-relative.

## Entity: Flight-Scanner Module Release

The published version of the fly-over-tracker module that both knobs must reference.

| Field             | Value / Rule                                                                  |
| ----------------- | ----------------------------------------------------------------------------- |
| Module            | fly-over-tracker (the dashboard's "flight-scanner")                           |
| Target version    | `0.5.0` (latest published)                                                    |
| Components tag    | `@sousa99/fly-over-tracker-components@0.5.0`                                  |
| Backend image tag | `ghcr.io/sousa99/fly-over-tracker-backend:0.5.0`                              |
| Invariant         | The widget declaration and the backend tag MUST resolve to this same version. |

## Entity: Widget Version Declaration

The dashboard's dependency on the embedded flight widgets.

| Field     | Location                        | Before   | After    | Rule                                                |
| --------- | ------------------------------- | -------- | -------- | --------------------------------------------------- |
| specifier | `package.json` (`dependencies`) | `^0.4.2` | `^0.5.0` | Caret range, per repository convention.             |
| resolved  | `pnpm-lock.yaml`                | `0.4.2`  | `0.5.0`  | Regenerated by `pnpm install`; frozen-install safe. |

**Validation**: The lockfile entry for `@sousa99/fly-over-tracker-components` must be `0.5.0`, and
`pnpm install --frozen-lockfile` must succeed.

## Entity: Backend Image Tag Declaration

The default (and overridable) tag for the flight-scanner backend service.

| Field       | Location                                                | Before  | After   |
| ----------- | ------------------------------------------------------- | ------- | ------- |
| service tag | `docker-compose.yml` (`fly-over-tracker-backend` image) | `0.3.0` | `0.5.0` |
| MCP tag     | `docker-compose.yml` (`fly-over-tracker-mcp` image)     | `0.3.0` | `0.5.0` |
| env default | `.env.example` (`HSH_FLY_OVER_TRACKER_BACKEND_VERSION`) | `0.3.0` | `0.5.0` |

**Rule**: Both compose references use the same `${HSH_FLY_OVER_TRACKER_BACKEND_VERSION:-<default>}`
expression, so the default appears in both places and must be updated in lockstep. An operator-set
override still wins.

## Entity: Current-Pins Documentation Row

The maintainer-facing record of the module's pinned versions.

| Field      | Location                                  | Before   | After    |
| ---------- | ----------------------------------------- | -------- | -------- |
| Components | `docs/versions.md` (fly-over-tracker row) | `^0.3.0` | `^0.5.0` |
| Backend    | `docs/versions.md` (fly-over-tracker row) | `0.3.0`  | `0.5.0`  |

**Validation**: The documented pins must equal the declared widget specifier and backend tag, with
no stale value remaining.

## Entity: Pin-Contract Test

A Vitest test (new) that enforces the invariants above across all declaration locations.

| Field      | Rule                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| Assertions | widget specifier == documented components pin; compose default == env default == documented backend pin |
| Inputs     | reads `package.json`, `docker-compose.yml`, `.env.example`, `docs/versions.md`                          |
| State      | fails on the pre-change declarations; passes once every declaration is updated                          |

## Relationships

```text
Flight-Scanner Module Release (0.5.0)
        │
        ├── drives ──► Widget Version Declaration (package.json + lockfile)
        ├── drives ──► Backend Image Tag Declaration (compose + .env.example)
        └── drives ──► Current-Pins Documentation Row (docs/versions.md)

Pin-Contract Test ── verifies consistency of ──► all three declaration entities
```

## Out of Scope (unchanged entities)

- Other modules' widget declarations and backend tags (bus-catcher, procrastinator-tracker,
  current-time).
- Dashboard runtime config (`public/config.json`) and its typed schema (`src/config.ts`).
- Proxy contracts (`deploy/nginx.conf`, `vite.config.ts`).
